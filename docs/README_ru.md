# Секунды на часах (Clock Seconds)

Покажите **секунды** на часах в строке состояния, переключайте одним касанием и держите **десяток часа красным**.<br>Никаких приватных классов производителя. Проверено на реальном устройстве с ColorOS 15; также рассчитано на Xiaomi, OnePlus, Honor, vivo и других крупных производителей.

## Возможности

| Возможность | Описание |
|------|------|
| Секунды | Часы в строке состояния показывают секунды (`HH:mm:ss` / `h:mm:ss a`, следуют системному формату 12/24 часа) |
| Касание для переключения | **Касание** часов в строке состояния переключает показ секунд; в настройках можно выбрать **долгое нажатие** |
| Красный десяток часа | **Десяток часа** окрашивается в красный (`1` в `13`, `0` в `05`); минуты и секунды сохраняют системный цвет. При однозначном часе (напр. `9:45`) десятка нет и он не трогается. Работает у всех производителей |
| Языки интерфейса | Интерфейс приложения локализован на **21 язык** (автоматически следует системному языку): 简体中文, English, 繁體中文, 日本語, 한국어, Türkçe, Русский, Tiếng Việt, ไทย, Deutsch, Español, Français, Українська, Polski, Português (Brasil), فارسی, العربية, Bahasa Indonesia, Italiano, Ελληνικά, ქართული |
| Сохранение состояния | Состояние хранится в `Settings.Secure`, общедоступно между процессами и сохраняется после перезапуска SystemUI |
| Совместимость | Проверено на ColorOS 15 / 16 / 17 (OPPO / OnePlus / realme); также работает «из коробки» на других производителях с root, например Xiaomi / Honor / Redmi. Без приватных классов производителя, поэтому безопасный режим LSPosed не срабатывает. Минимум Android 10 |

## Установка

1. Скачайте последний APK со страницы [**Releases**](https://github.com/kelebao/ClockSeconds/releases/latest)
2. Включите модуль в **LSPosed**, область: **Системный интерфейс (`com.android.systemui`)**
3. Перезапустите процесс SystemUI или перезагрузите устройство
4. Страницу настроек открывайте из **менеджера LSPosed** (значок на рабочем столе не создаётся)

> Требуется root (LSPosed). Чтобы выдать разрешение `WRITE_SECURE_SETTINGS` для записи в `Settings.Secure`:
> ```bash
> adb shell pm grant io.github.kelebao.colorosclockseconds android.permission.WRITE_SECURE_SETTINGS
> ```
> Без разрешения переключение по-прежнему работает касанием часов в строке состояния (это действие выполняется внутри процесса SystemUI, который уже обладает правом).

## Использование

- **Касание часов в строке состояния**: переключает показ секунд (жест по умолчанию).
- Переключение реализовано через глобальное попадание по касанию, поэтому оно **никогда не конфликтует со «смахиванием шторки уведомлений»** — чистое касание переключает, свайп по-прежнему опускает шторку. При желании жест можно сменить на **долгое нажатие** в настройках.
- На странице настроек отображаются текущее состояние, выбранный жест и кнопка обновления.

## Как это работает

Модуль перехватывает только **SystemUI**, используя проверенный подход legacy Xposed,
и **ни разу не касается приватных классов производителя**, поэтому внутреннее состояние системы не ломается и безопасный режим LSPosed не срабатывает:

- **Секунды**: хук стабильного `TextView.setText` (after) кэширует исходный текст, который система выводит на часы строки состояния,
  затем хук `TextView.onDraw` (before) после установки текста системой перезаписывает отображение на `исходныйТекст:ss`,
  управляемый `Handler` с периодом 1 секунда. Добавленные секунды наследуют собственный цвет текста часов (измерено `#ccffffff`).
  Дополнительно десяток часа окрашивается в красный (красный `ForegroundColorSpan` на этом одном символе) — красный держится и при включённом, и при выключенном показе секунд;
  минуты и секунды не окрашиваются; при однозначном часе десятка нет и он не трогается.
- **Переключение**: панель уведомлений ColorOS перехватывает касания в области строки состояния, поэтому собственный `OnTouchListener` часов событий не получает.
  Модуль поэтому перехватывает глобальный `View.dispatchTouchEvent` и переключает `Settings.Secure` только когда нажатие попадает
  в границы распознанных часов на экране и почти не смещается (касание) либо удерживается 500 мс (долгое нажатие). Модуль **не потребляет**
  никакие события касания, поэтому смахивание шторки уведомлений работает как обычно.

## Экономия заряда

- **Секунды ВКЛ**: модулю нужен таймер с периодом 1 секунда для обновлений (неотъемлемая цена показа секунд — около 60 перерисовок часов в минуту).
- **Секунды ВЫКЛ**: модуль **немедленно останавливает этот таймер** (`stopTicker`) — никаких посекундных пробуждений и межпроцессных чтений.
  Он возвращается к исходному ритму системы «обновление раз в минуту», поэтому выключение показа секунд действительно экономит заряд.
- Состояние кэшируется **внутри процесса** (`sSecondsEnabled`), поэтому таймер не читает `Settings.Secure` каждую секунду (что избегает посекундного IPC).
- Никаких форматировщиков времени не создаётся: модуль переиспользует исходный текст системы и лишь добавляет `:ss`, поэтому накладных расходов на форматирование нет.
- Таймер держит только **слабую ссылку** на представление и продолжает работу, пока представление `isAttachedToWindow()`; после уничтожения представления выходит автоматически.

## Сборка

Требуются **JDK 17+** (рекомендуется 17 или 21) и **Android SDK Platform 35** (Build-Tools 35 устанавливается автоматически через AGP).

```bash
export JAVA_HOME=/path/to/jdk-17-or-21
./gradlew assembleDebug
```

## Резервная копия и продолжение разработки (важно)

В каталоге `ClockSeconds/` нужно сохранять **все файлы, кроме `build/` и `.gradle/`** (исходники весят лишь около 140 КБ):

| Категория | Файл | Примечание |
|------|------|------|
| Скрипты сборки | `settings.gradle.kts`, `build.gradle.kts`, `app/build.gradle.kts`, `gradle.properties` | Версия, зависимости, параметры компиляции |
| Gradle Wrapper | `gradlew`, `gradlew.bat`, `gradle/wrapper/*` | Фиксирует Gradle 8.14.5 |
| Исходный код | `app/src/main/java/**` (3 файла `.java`) | Основная логика модуля |
| Ресурсы | `app/src/main/res/**` | Строки (китайский по умолчанию + 21 локаль values-xx), тема |
| Метаданные Xposed | `app/src/main/resources/META-INF/xposed/*` | Класс входа, область, версия API |
| Манифест | `app/src/main/AndroidManifest.xml` | Разрешения, Activity |
| Документация | `README*.md` | Документация на 21 языке |
| CI | `.github/workflows/release.yml` | Подписанные сборки по тегу |

## Диагностика

<details>
<summary>Развернуть шаги диагностики</summary>

Проверьте logcat:

- **Release-сборки** вырезают всю диагностическую логировку через гейт `BuildConfig.DEBUG` (меньше и чище); в logcat от этого модуля ничего нет.
- Для диагностики временно установите **debug-сборку** (`assembleDebug`, подписанную тем же производственным ключом, поэтому её можно поставить поверх release), затем фильтруйте по TAG:

  ```bash
  adb logcat -s ColorOSClockSeconds
  ```

- Если секунды не показываются совсем: сначала убедитесь, что в LSPosed отмечена область SystemUI и выполнён перезапуск; затем проверьте, не сохранился ли переключатель как выключенный —
  прочитать / принудительно записать через adb:

  ```bash
  adb shell settings get secure coloros_clock_seconds_enabled   # 1=вкл 0=выкл
  adb shell settings put  secure coloros_clock_seconds_enabled 1
  ```

- Если не работает на устройстве без ColorOS: установите debug-сборку и посмотрите строки `candidate:` / `CONFIG CLOCK:` в логе,
  чтобы понять, покрыты ли имя ресурса / имя класса часов строки состояния вашего устройства правилами распознавания; если нет — достаточно добавить одну строку правила.

</details>
